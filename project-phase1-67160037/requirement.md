# Requirement Specification: ระบบข้อมูลบอร์ดเกมและการจอง (Pno=8)

- **นิสิต:** พิชชาพร (รหัสนิสิต 67160037)
- **โครงงาน:** ระยะที่ 1 (W5: DB/Requirement)

## วัตถุประสงค์ของระบบ

เป็นระบบสำหรับจัดการข้อมูลบอร์ดเกมและให้บริการจองโต๊ะของร้านคาเฟ่บอร์ดเกม โดยพนักงานสามารถจัดการแคตตาล็อกเกมได้ ลูกค้าสามารถจองวันเวลาพร้อมระบุบอร์ดเกมที่ต้องการเล่นล่วงหน้า และเขียนรีวิวให้กับเกมที่เคยเล่น เพื่อให้ร้านเตรียมการได้ถูกต้องและลูกค้ารายอื่นใช้ประกอบการตัดสินใจ

**กลุ่มผู้ใช้เป้าหมาย**

| กลุ่มผู้ใช้               | สิทธิ์การใช้งาน                                                  |
| ------------------------- | ---------------------------------------------------------------- |
| **ลูกค้า / ผู้ใช้ทั่วไป** | ค้นหา-ดูรายละเอียดเกมพร้อมรีวิว, เขียนรีวิว, จองโต๊ะพร้อมระบุเกม |
| **พนักงาน**               | จัดการบอร์ดเกม หมวดหมู่ และรายการจอง                             |

## รายการ Use Case หลัก

| #   | Use Case                                                                 | ผู้กระทำ |
| --- | ------------------------------------------------------------------------ | -------- |
| 1   | เพิ่ม แก้ไข และลบข้อมูลบอร์ดเกมในระบบ                                    | พนักงาน  |
| 2   | ค้นหาบอร์ดเกมที่เหมาะสมกับจำนวนผู้เล่น (`minPlayers`, `maxPlayers`)      | ลูกค้า   |
| 3   | จองโต๊ะ (ระบุวัน เวลา จำนวนคน) พร้อมระบุบอร์ดเกมที่ต้องการเล่นล่วงหน้า   | ลูกค้า   |
| 4   | ดูรายการการจองทั้งหมด และอัปเดตสถานะการจอง (รออนุมัติ/ยืนยันแล้ว/ยกเลิก) | พนักงาน  |
| 5   | จัดการหมวดหมู่ของบอร์ดเกม                                                | พนักงาน  |
| 6   | ดูรายละเอียดบอร์ดเกมพร้อมรีวิว และเขียนรีวิวให้บอร์ดเกม                  | ลูกค้า   |

## รายการ Resource หลักและความสัมพันธ์

ระบบนี้ประกอบด้วย Resource หลักดังนี้:

1. `categories` (หมวดหมู่) — One-to-Many กับ `boardgames`
2. `boardgames` (บอร์ดเกม) — เก็บ `name`, `min_players`, `max_players` เชื่อมกับ `categories` ผ่าน FK
3. `reviews` (รีวิว) — One-to-Many จาก `boardgames` (หนึ่งเกมมีได้หลายรีวิว, ลูกค้าเป็นคนเขียน)
4. `customers` (ลูกค้า) — One-to-Many กับ `reservations`
5. `reservations` (การจอง) — เก็บวัน เวลา จำนวนคน สถานะ เชื่อมกับ `customers` ผ่าน FK
6. `reservation_games` (ตารางเชื่อม) — Many-to-Many ระหว่าง `reservations` กับ `boardgames` (การจอง 1 ครั้งเลือกเล่นได้หลายเกม และ 1 เกมถูกเลือกในการจองได้หลายครั้ง)

**สรุปความสัมพันธ์:**

- `categories` 1 --- N `boardgames`
- `boardgames` 1 --- N `reviews`
- `customers` 1 --- N `reservations`
- `reservations` M --- N `boardgames` ผ่าน `reservation_games`
